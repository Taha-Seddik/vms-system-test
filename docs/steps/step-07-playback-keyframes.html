Playback and intelligent keyframes

Step 7 turns the MP4 files from Step 6 into an authenticated playback library. Operators can filter recordings, play and seek, change speed, capture a frame, download the original file, and jump through real FFmpeg-generated JPEG previews every 30 seconds.

Completed: 26 July 2026 Media: Protected MP4 Timeline: 30-second JPEGs Access: Administrator + Operator

1. Assessment requirement

The PDF requires browsing and replaying recordings with a timeline, play/pause, seek, fast forward, speed control, snapshot, and download. It separately requires thumbnail previews every 30–60 seconds that let an operator jump directly to a keyframe and move quickly through long recordings.

Review

Navigate

3. Playback workflow

Protected storageGUID MP4

Video playerseek + snapshot
  1. The library requests only Completed recording metadata through the authenticated API.
  2. Selecting a row requests its detail/timeline and MP4 using the Bearer token.
  3. The browser converts the authenticated MP4 response into a temporary Blob URL.
  4. The HTML video element provides decoding, native controls, timeline events, and current frames.
  5. Changing selection revokes the old Blob URL so browser memory is released.

These are real images, not duplicated placeholders.

FFmpeg opens the completed MP4 at each timestamp, decodes one frame, scales it to 320 pixels wide, and writes a JPEG. FFprobe verified the live 0-second and 30-second outputs as decodable MJPEG images.

The configurable interval is constrained to the PDF’s allowed 30–60 second range and defaults to 30 seconds. A background service backfills older completed recordings. Opening a detail page also guarantees missing keyframes immediately.

5. Media security and safe paths

Role boundary
Every playback route requires Administrator or Operator; Viewers receive HTTP 403.
No JWT URL
The frontend fetches blobs with an Authorization header. Tokens are never appended to media or thumbnail URLs.
No client path
Clients send recording/keyframe GUIDs only. The server loads server-generated file names from PostgreSQL.
Root confinement
The path resolver rejects directory components, incorrect extensions, and paths outside the recording root.
Safe download
The attachment name is generated from persisted camera/time/mode values and invalid filename characters are replaced.
Playable only
Failed or still-running recordings cannot be served through the MP4 endpoint.

10. Boundaries and next step

The browser currently fetches the complete authenticated MP4 into a Blob before playback. This is simple and secure for the assessment recordings, but very large production archives would benefit from cookie-authenticated or signed short-lived streaming URLs. The API already supports range requests for that future transport.

Keyframes are visual navigation aids, not AI scene recognition. Recording deletion/retention policies are not assessment Step 7 requirements. Global cross-resource search remains Step 9.

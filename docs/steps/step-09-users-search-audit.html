Users, search, and audit logs

Step 9 completes day-to-day administration. Administrators manage Identity accounts, roles, passwords, and Viewer assignments; operators search operational resources; and important successful writes become durable, filterable audit records.

Completed: 26 July 2026 Identity: ASP.NET Core Identity Search: Four resource categories Audit: PostgreSQL

1. Assessment requirement

The PDF requires user and role management, permissions, audit logs for important user activities, and search across cameras, recordings, events, and users. Search must support date, camera, camera group, status, and event-type filters.

Viewer assignments remain mandatory from Step 2. Step 9 exposes those assignments to Administrators instead of weakening the assignment-aware authorization already enforced by the API.

2. Completed outcome

Users

Create, update, disable, reset passwords, change roles, delete, and assign cameras to Viewers.

Search

One workspace searches cameras, recordings, events, and Administrator-visible users with shared filters.

Audit

Successful writes and login/logout activity record actor, action, resource, description, and timestamp.

3. Dependencies and reuse

ASP.NET Core Identity

Reuses the Step 2 account, password hashing, role, security-stamp, and lockout infrastructure. No custom password cryptography was added.

EF Core and PostgreSQL

Stores the new durable audit records and queries the existing camera, recording, event, assignment, and user tables.

React and Material UI

Provide the Administrator user editor, global search workspace, and audit activity screen using the existing frontend stack.

Step 9 adds no new NuGet or npm dependency. It deliberately builds on the libraries and database already used by the project.

4. User-management flow

1

Administrator enters account details

Username, display name, strong password, role, enabled state, and Viewer assignments are submitted.

2

Identity performs security work

ASP.NET Core Identity validates and hashes passwords, normalizes usernames, maintains roles, security stamps, and lockout data.

3

Assignments are validated

A Viewer must have at least one real camera. Administrator and Operator accounts cannot carry Viewer assignments.

4

Security changes revoke sessions

Password, role, or disabled-state changes revoke active sessions so old JWTs stop working immediately.

The current Administrator cannot delete their own account, disable it, or remove their own Administrator role. This prevents an accidental lockout of the management interface.

5. Search flow

GET /api/search runs bounded database queries over four existing domains and returns grouped results. It does not copy data into a separate search index, which keeps this assessment implementation small and consistent.

6. Audit flow

Authentication writes explicit Login and Logout audit records. A small middleware observes every other authenticated successful POST, PUT, PATCH, or DELETE response and stores a normalized record. Failed requests are not reported as successful operations.

Recorded fields

UTC timestamp, user ID, username snapshot, action, resource type, resource ID when available, and description.

Consumers

The Administrator Audit Activity page shows full filtered history. The Command Center shows recent actions performed by Operators.

Username is stored as a snapshot, so an audit remains readable even if the related user is later deleted. Audit rows deliberately do not cascade with user deletion.

7. Security rules

  • Only Administrators can list or mutate users and read full audit history.
  • Administrators and Operators can use system-wide search; Viewers receive 403.
  • Operators never receive user search results.
  • Viewer creation/update fails unless at least one valid camera is assigned.
  • Passwords are processed by Identity and never returned by the API.
  • Role, password, and disabled-state changes revoke active sessions.
  • Self-deletion, self-disable, and self-role removal return 409.

11. What you should understand

Identity still owns passwords

The new service orchestrates Identity APIs. It does not implement custom hashing or password-reset cryptography.

Assignments are authorization data

They are not labels. Camera access reads the persisted assignment on every Viewer camera request.

Search respects roles

A global endpoint does not mean global disclosure. Operators receive no user results and Viewers cannot call it.

Events and audit logs differ

Events describe operational conditions. Audit logs answer who performed a successful system-changing action.

12. Boundaries and next step

Search is database-backed and bounded to 50 results per category; an external search engine is unnecessary for this assessment. Audit logs are append-only through the application and have no retention policy. Production retention/export belongs outside the requested scope.

3. Health architecture

MediaMTX remains the media router. The API does not decode frames itself; it starts a bounded FFprobe process against the RTSP URL, interprets the result, and persists the operational state that the UI and the next dashboard step consume.

FFmpeg feed Generated H.264 source
->
MediaMTX RTSP routing
->
FFprobe Safe process + timeout
->
Health service Transition logic
->
PostgreSQL Status + events
Periodic monitor Every 15 seconds
->
Enabled cameras Disabled cameras skipped
->
React UI 15-second polling
Events are transition-based

Repeated failed checks do not create an event flood. A Camera Offline event is added only when a camera enters Offline. A Camera Reconnected event is added only when the previous state was Offline and a new probe succeeds.

5. Data and lifecycle rules

Stored field Meaning Updated by
ConnectionStatus Unknown, Online, Offline, or Disabled Enable/disable and health checks
LastCheckedAt Last completed probe, successful or failed Every connection test
LastHeartbeatAt Last time a video stream was confirmed Successful probe only
Resolution / FPS Measured stream metadata, not user-entered claims Successful FFprobe result
RecordingStatus NotRecording until Step 6 owns recording processes Future recording service
LastConnectionError Bounded, credential-safe operational message Failed probe
Enable is not the same as Online

Enabling a camera changes it to Unknown. Only a successful media probe can make it Online. Disabling sets Disabled immediately and removes the camera from background probing.

6. Frontend management workspace

Administrators receive a protected Manage navigation item and a dedicated responsive workspace. Operators can test connections from the normal camera list. Viewers see health for assigned cameras but cannot test or mutate camera configuration.

Camera cards

Show source, group, status, resolution, FPS, recording state, heartbeat, and the latest error.

Lifecycle controls

Add/edit dialog, enable switch, connection test, and confirmed camera deletion.

Group controls

Create, rename, and delete groups. Deleting a group leaves its cameras intact and ungrouped.

What MediaMTX does here

MediaMTX is not the database and does not own VMS camera records. It is the media transport layer: generated FFmpeg publishers send RTSP to it, FFprobe reads RTSP from it, and browsers later consume its HLS output. PostgreSQL remains the source of truth for camera names, groups, authorization, health, and events.

FfprobeCameraProbe.cs Safe process arguments 
var startInfo = new ProcessStartInfo
{
    FileName = executable,
    RedirectStandardOutput = true,
    RedirectStandardError = true,
    UseShellExecute = false,
    CreateNoWindow = true
};

startInfo.ArgumentList.Add("-rtsp_transport");
startInfo.ArgumentList.Add("tcp");
startInfo.ArgumentList.Add("-show_entries");
startInfo.ArgumentList.Add("stream=codec_name,width,height,r_frame_rate");
startInfo.ArgumentList.Add("-of");
startInfo.ArgumentList.Add("json");
startInfo.ArgumentList.Add(rtspUrl);

ArgumentList passes the URL as one argument and never asks a shell to interpret it. A linked cancellation source enforces the configured timeout and kills the process tree on timeout.

CameraHealthService.cs Transition events 
if (resultingStatus == CameraConnectionStatus.Offline
    && previousStatus != CameraConnectionStatus.Offline)
{
    database.SystemEvents.Add(new SystemEvent
    {
        Type = SystemEventType.CameraOffline,
        Severity = EventSeverity.Warning,
        Status = EventStatus.Open
    });
}
else if (resultingStatus == CameraConnectionStatus.Online
         && previousStatus == CameraConnectionStatus.Offline)
{
    database.SystemEvents.Add(new SystemEvent
    {
        Type = SystemEventType.CameraReconnected,
        Severity = EventSeverity.Information,
        Status = EventStatus.Closed
    });
}

10. Boundaries and what comes next

Deliberately deferred

SignalR, dashboard metrics, active alarms, recording state, full event management, and media authorization belong to later approved steps.

Current tradeoffs

Four probes run sequentially to keep resource use predictable. Group rename and delete use simple browser confirmation UI. The ffmpeg package increases the API image size but supplies a known-compatible FFprobe binary.

Before Step 4, understand:

  1. PostgreSQL camera rows are now the source of truth. The original hard-coded camera catalog has been removed.
  2. LastHeartbeatAt means a real video probe succeeded; LastCheckedAt also changes after failures.
  3. Offline and reconnected events already exist. Step 4 can count them as recent incidents, and Step 8 will add their full UI.
  4. Step 4 should query this persisted state for total, online, offline, and camera-health metrics instead of probing media directly.
  5. RecordingStatus intentionally remains NotRecording until Step 6 creates and supervises real FFmpeg recording processes.
Next approved step: Command center dashboard

Step 4 will turn camera health and event state into operational metrics, offline-camera lists, incidents, active alarms, storage and recording information, active users, uptime, operator activity, and automatic SignalR updates with a polling fallback.

Central command-center dashboard

Step 4 turns persisted Identity sessions, camera health, recording state, storage capacity, and system events into one operational view for Administrators and Operators. SignalR invalidates the snapshot immediately, while the same REST contract provides a dependable 30-second polling fallback.

Completed: 26 July 2026 Realtime: Authenticated SignalR Fallback: 30-second REST polling Access: Administrator + Operator

1. Assessment requirement

The assessment requires a dashboard with system overview, camera and recording status, storage usage, active users, total and online/offline cameras, active streams and recordings, recent events, camera health, and uptime. Its central command center must also present a camera wall, live event panel, offline cameras, recording failures, active alarms, storage health, recent incidents, and operator activity without manual refresh.

Summarize

Provide exact operational counts and filesystem capacity from the persisted VMS state.

Prioritize

Separate open alarms, offline cameras, recording failures, incidents, events, and operator activity into usable panels.

Refresh

Update connected screens through authenticated SignalR and keep a polling path when the realtime connection drops.

4. Dashboard architecture

REST remains the source of truth. SignalR sends a small change message, and the client retrieves a fresh, internally consistent dashboard snapshot. This avoids duplicating aggregation rules across push messages and polling.

Identity sessions Users + activity
Cameras Health + recording state
SystemEvents Alarms + incidents
Recording volume Capacity + file bytes
->
CommandCenterService One measured snapshot
->
REST API Polling source of truth
->
React dashboard Responsive panels
Domain change Health, camera, session
->
SignalR hub DashboardChanged
->
REST refresh Immediate snapshot reload

CommandCenterService

Aggregates cameras, sessions, Identity roles, events, storage, and uptime into one response contract.

DashboardUpdatePublisher

Uses IHubContext outside the transient Hub to broadcast a monotonic revision, timestamp, and change reason.

Storage provider

Creates and inspects the configured recording path, measures filesystem capacity, and totals existing recording files.

Authorization

REST and SignalR both require the existing OperatorOrAdministrator policy. Viewers receive HTTP 403.

6. Command-center UI

Administrator and Operator home routes now open the command center. Viewers continue directly to their assignment-filtered camera screen. The application shell uses the familiar administration pattern of a fixed left navigation rail on desktop and a solid mobile header with an off-canvas menu.

Readable hierarchy

A restrained hero, three-column metric grid, consistent panel surfaces, and meaningful spacing make the most important operational state easy to scan.

Controlled previews

Alarm, incident, failure, activity, offline-camera, and event cards show no more than five rows, preventing long lists from overwhelming the command center.

Detail drawers

View details and View all actions open a right-side panel with the complete API result, full descriptions, dates, and clear close behavior.

Connection indicator

The dashboard hero identifies Live, Reconnecting, or Polling state. Automatic reconnect is attempted first; the 30-second timer always remains active as a fallback.

Sidebar overflow correction

The Drawer owns the fixed width while its internal navigation uses 100% of the available content box. Horizontal overflow is clipped at the page, Drawer, navigation, content, and footer boundaries; long labels use ellipsis instead of widening the sidebar.

8. Important implementation code

CommandCenterController.cs Shared REST snapshot 
[ApiController]
[Authorize(Policy = AppPolicies.OperatorOrAdministrator)]
[Route("api/command-center")]
public sealed class CommandCenterController(
    CommandCenterService commandCenter) : ControllerBase
{
    [HttpGet]
    public async Task<ActionResult<CommandCenterResponse>> Get(
        CancellationToken cancellationToken) =>
        Ok(await commandCenter.GetAsync(cancellationToken));
}
CommandCenterService.cs Active users 
var activeUsers = await database.UserSessions
    .Where(session =>
        session.RevokedAt == null
        && session.ExpiresAt > now
        && session.LastActivityAt > now.AddMinutes(-5))
    .Select(session => session.UserId)
    .Distinct()
    .CountAsync(cancellationToken);
DashboardUpdatePublisher.cs Realtime invalidation 
var message = new DashboardChangedMessage(
    Interlocked.Increment(ref _revision),
    timeProvider.GetUtcNow(),
    reason);

await hubContext.Clients.All.SendAsync(
    "DashboardChanged",
    message,
    cancellationToken);
commandCenterConnection.ts Reconnect and token 
const connection = new HubConnectionBuilder()
  .withUrl(`${apiBaseUrl}/hubs/command-center`, {
    accessTokenFactory: () => accessToken,

10. Boundaries and what comes next

Deliberately deferred

Camera tiles show operational status rather than video. Multi-camera HLS playback, layout switching, fullscreen, digital zoom, and snapshots are Step 5.

Current empty states

Active recordings and recording failures remain empty in normal operation until Step 6 starts real recording processes. The panels and event queries are already functional.

Activity depth

Operator activity currently shows login/logout behavior. Detailed write-operation audit records arrive in Step 9.

Dependency audit

npm reports two high React Router advisories in its current release line. They concern server/RSC behavior not used by this client-only SPA, and no non-breaking patched release is currently offered. Recheck during Step 10 security hardening.

Before Step 5, understand:

  1. The command center is system-wide and therefore unavailable to Viewers; Viewers continue to their assigned-camera screen.
  2. SignalR announces that state changed. REST still computes the authoritative dashboard snapshot for push and polling paths.
  3. Camera status wall tiles are ready to become video players, but HLS lifecycle and controls intentionally remain separate.
  4. The recording volume now exists and is measured, but no recording file is created until the real FFmpeg workflows in Step 6.

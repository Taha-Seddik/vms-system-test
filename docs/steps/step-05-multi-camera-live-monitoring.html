The browser does not connect directly to RTSP. MediaMTX converts each RTSP source into HLS. HLS.js reads the playlist and appends segments to a normal HTML video element. Browsers with native HLS support use that native path instead.

4. Viewer assignment rule

Security is applied before rendering.

The wall loads GET /api/cameras/accessible. The backend returns all cameras to Administrators and Operators, but only persisted assignments to a Viewer. The seeded Viewer therefore receives exactly camera-1 and camera-2.

5. What each tile control does

Fullscreen
Requests browser fullscreen for the complete tile, preserving its overlay and controls.
Digital zoom
Cycles 1×, 1.5×, and 2× by scaling video inside a clipped tile; it does not pretend the camera has optical/PTZ zoom.
Snapshot
Draws the current decoded frame to a canvas and downloads a timestamped PNG.
REC badge
Uses persisted camera recording state, refreshed every five seconds during activity.
Empty cell
Clearly marks capacity when a 9/16 layout has more cells than the four demo cameras.

6. New dependency: HLS.js

hls.js 1.6.16 is the browser HLS client. Chromium-family browsers do not generally play an HLS playlist directly. It adds manifest parsing, segment loading, Media Source attachment, and bounded network/media recovery. It does not generate, store, or authorize streams. See the official HLS.js API guide.
